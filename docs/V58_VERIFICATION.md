## 本次发现并修复的问题

- 关闭捕获源后，旧 HWND 残留导致计时精度请求及采集状态未释放。现在清空来源，停止 WGC、Clock，释放本程序 WinMM 请求，忘记豆数基准；保留已有冷却和触发次数。来源副作用用单独锁串行化，配置版本拒绝在途旧结果。
- 同一局部图片被反复消费。现在以捕获序号识别新帧，旧帧不补确认、不刷新游戏时钟的有效时间；像素完全一致的新帧才复用分类结果，像素变化重新识别。
- 放大窗口的客户端尺寸发生变化而 WGC 内容尺寸相同时，旧尺寸状态可能持续等待。现在丢弃过渡帧，再接受匹配的新帧并重定位。
- 相同性能启用状态在窗口缩放时唤醒采样线程。现在重复启用直接返回，保持约 1 Hz。
- 主界面暂存“扫描中”提示可能滞留。现在后台请求结束即清除提示，不等待提示的超时。
- 旧布局的字号和小标题按钮边距问题在最终最小化/恢复与视觉检查中确认正常。

## 受控测量及实际边界

最终 WGC 合成窗单次测试：重扫 API 返回 **0.418 ms**；4→3 绘制至少豆触发 **78.81 ms**，其中连续确认 **52.02 ms**；960×540→1280×720 绘制至有效重新定位 **132.20 ms**。重扫、放大和暂停单次扫描都没有改变原 deadline 或增加假消费。

旧/新定位对照在一个 1280×720 空白输入上，实际托管分配从 **521,059,608** 降为 **2,646,160 bytes**，单次耗时 **160.21→136.20 ms**。移除候选内常量数组分配；相同输入下检测框、数量和分数保持一致。这不是程序工作集、长期内存泄漏检测或所有画面性能的平均值。

性能模块测试中，受控单线程负载检测到 CPU **6.17%**（8 个逻辑核心归一化）；GPU 无本进程对应数据时返回空值及原因。主界面真实性能截图处于静态设计测试，不能代表开启 MuMu 连续监测时的占用。

监测时 WGC 读回上限约 60 Hz；选择来源但尚未开始监测的预览模式仍有约 20 Hz 捕获、约 10 Hz 豆子轮询及约 20 Hz 游戏时钟轮询。隐藏预览只减少绘制；**暂停监测**才会停止持续捕获和两识别线程。暂停后的资源曲线仍按 1 Hz 统计本程序，可在设置里关闭。未承诺预览模式完全零后台开销。

未测量真实 MuMu 多局独立准确率、鼠标卡顿改善比例、游戏渲染至浮窗的端到端延迟、长期泄漏或 GPU 占用改善比例。WGC 在最小化或源不再渲染时可能没有新帧；暂停单次兼容扫描仍需要源窗口露出。新帧处理修复能消除旧帧重复确认机制，没有据此训练新通用 AI 或宣称全设备 200 ms 上限。

## 检查过程中的失败与纠正

最初 capture58 调用误把目录传作报告 txt 文件，导致写入失败；纠正参数后 19 项通过，入口已增加异常报告。最初旧 UI 检查与其他 GUI 窗口同时运行，菜单焦点受到干扰；隔离顺序执行后 8 项通过。首次 Resize 正向检查发现上述真实源关闭资源问题，修复后 25 项全部通过，无 SKIP。

新增 PowerShell 检查脚本第一次因无 BOM 的 UTF-8 在 Windows PowerShell 5 中误读中文报告名，未能找到实际已成功生成的音效报告。保存为 UTF-8 BOM 后纠正；这属于检查入口编码问题，并非音效回归。
