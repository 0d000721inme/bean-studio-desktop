# V5.8 · 快捷操作与低干扰显示

> 历史记录：本页描述 V5.8 本地构建阶段，当前主分支为 V5.8.1；请先看 [本版交接](NEXT_MODEL_V581.md) 和 [发布记录](PUBLICATION.md)。

本说明对应本地 Windows V5.8 工程。它不代表 V5.8 已发布到 GitHub，也不替代本次实际构建和验证报告。旧版本下载与历史测试说明仍保留用于回溯。

## 从选择窗口开始

1. 退出之前的 Bean Studio，手动启动 MuMu 并打开游戏。
2. 在主界面选择“MuMu 安卓设备”，点“重新扫描”，等待两侧豆子定位完成。
3. 选择想监测的左侧或右侧，点“开始监测”。第一次确认数量只建立基准。
4. 需要更轻的显示时打开悬浮窗，并在“快捷键与浮窗”中选择风格。

## 全局快捷键

| 操作 | 默认组合 | 行为 |
| --- | --- | --- |
| 悬浮窗快速开关 | Ctrl + Alt + F8 | 打开或关闭置顶浮窗，主界面保持原状态 |
| 重新扫描豆子区域 | Ctrl + Alt + F9 | 后台重新定位所选窗口，保留原冷却 |

不用先点回 Bean Studio。放大 MuMu、改变分辨率或遇到旧扫描框错位时按重新扫描即可；扫描不会强制把游戏切到前台。已有扫描尚未完成时不会创建另一组持续捕获。

修改方式：打开“快捷键与浮窗”，点对应输入框，再按新的组合键。至少包含 Ctrl、Alt 或 Win；F12 属于系统保留按键，不可选。Backspace 或 Delete 清空当前一项，Tab 移到下一项，Esc 取消整个设置窗。可以关闭“启用全局快捷键”，保留已有组合供以后恢复。

输入期间临时注销组合，避免录入动作误开浮窗或扫描。保存时通过 Windows 检查是否被其他程序占用，冲突会显示具体组合和失败原因，设置窗保持打开。失败保留之前有效的绑定；文件写入失败也回滚本次变更。程序关闭时注销快捷键，不安装全局键盘 hook、不记录其他按键。

**暂停中的扫描存在可见性限制。** 暂停会停止持续 WGC 捕获、豆子和游戏时间读取。此时按重新扫描仅截一次兼容桌面截图；请先露出完整游戏窗口，移开遮挡的主界面，不能在最小化状态下扫描。一次扫描结束后继续保持暂停，不清除旧冷却。

## 四种悬浮窗

| 风格 | 适用情况 |
| --- | --- |
| 专注 | 默认。比经典更小，保留侧切换与必要提醒 |
| 纯数字 | 优先看剩余秒数，尽量减少背景和状态文字 |
| 细条 | 横向布局，适合贴在画面边缘 |
| 经典 | 完整显示豆数、状态和恢复点 |

各风格保留左 / 右切换、拖动移动与双击返回主界面。重复点击当前侧不会重新建立基准；换侧会建立该侧的新基准，避免把两侧数量差当成消费。

“大小”范围为 80–140%，默认 100%；“背景强度”范围为 0–40%，默认 18%。这调整背景，不把文字一起变透明。纯数字样式进一步减少背景；小尺寸可能使文字更难读，可按实际游戏位置调整。

默认只显示整秒，减少百分之一秒数字持续跳动带来的注意力干扰。内部计时仍按单调时钟保存完整的 15 秒期限，开始 / 到期音效不受整秒显示影响。最后 5 秒使用紧急颜色，数字配有描边，不用持续闪烁吸引注意。可以关闭恢复点显示，减少浮窗高度。

## CPU、GPU 与内存图表

图表统计 **Bean Studio 当前进程**，不是 MuMu、游戏进程或整机。约每秒更新一次，趋势用于比较本程序不同状态下的负担，不把每帧刷新变成额外负载。

CPU 按本进程 CPU 时间和系统逻辑处理器数计算百分比；内存为进程工作集，物理内存总量可读时也显示工作集所占百分比。GPU 来自 Windows 对当前进程的 GPU Engine 性能计数器，显示该进程最忙引擎的利用率；系统、驱动或计数器不可用时显示不可用，不能把这种情况解读成 0% 占用。它与任务管理器的整机 GPU 总览统计范围不同。

在设置中关闭资源图表可停止额外采样。隐藏主界面定位预览只减少预览绘制，豆子与游戏时间识别继续；暂停监测才会停止持续识别。已有冷却与音效自然到期仍继续。

## 减少占用与误确认的方式

- 监测时只消费新窗口帧，最多约 60 次读回/秒；非监测预览约 20 次。上限不代表实际游戏帧率。
- 豆子与时间识别分别跟踪帧序号。同一 WGC 帧不会重复作为多个确认样本，旧时间图片也不会反复刷新“新鲜”状态。
- 相同豆子局部像素可复用分类，仍以真正的新帧进行连续状态判断。画面变化后重新分类，不降低亮 / 暗 / 无效判定门槛。
- 扫描放在工作线程；界面与资源图表刷新和识别分开。浮窗仅在实际可见内容变化时重新绘制表面。

WGC 通常能取得被普通外部窗口覆盖的 MuMu 内容；窗口最小化、模拟器停止渲染、游戏特效盖住 HUD、选错区域或分辨率过低仍可能未确认。WGC 不可用时，兼容截图只能读取无遮挡的可见屏幕。没有通过游戏进程注入或内存读取绕过这些限制。

如果关闭或重启了所选 MuMu 窗口，程序会释放旧来源捕获、停止读取时间，清除旧扫描框与数量基准，提示重新选择来源。已经开始的 15 秒冷却及触发记录继续保留；关闭窗口不会被当作新回合，也不会假触发少豆。失效窗口的重扫请求会拒绝，重新选择有效窗口后建立新基准。

## 原规则与音效仍保留

初次确认只建立基准；确认减少时从该时刻设置完整 **15.000 现实秒**，已有冷却中再次减少也重新设置完整 15 秒。增长不触发。未知帧、技能黑屏和遮挡不清空旧冷却，也不伪造 0 豆。

连续确认所选侧四格全空后显示“对方已无豆”，0 / 4 颗；恢复豆子后回到数字状态，增长不触发新冷却。最后一豆消费仍产生底层冷却，所以开始与到期提示仍按原规则播放。

游戏时间仅接受 0–60 秒，支持两位整数及低于 10 秒的一位整数 + 两位小数。少豆时有可确认游戏时间，就固定显示“当时游戏时间 − 15”的恢复点；中途补读则减去剩余现实冷却并标为 ≈。游戏时间可能暂停，整数存在取整误差，估算并非游戏恢复事件的精确读取。未确认时不猜 60 秒，可点“校准”检查实际裁图。

音效设置继续支持开始 / 结束独立开关、自定义文件、试听和 0–100% 音量。PCM WAV 与 FLAC 可作无损音效；MP3、M4A、AAC、MP4/M4V 的实际支持取决于 Windows 解码器，视频仅播放音轨。手动清空冷却取消那一轮结束提示；暂停保留旧冷却，到期仍可响。

## 配置、构建与验证

界面和快捷键文件为 `%LOCALAPPDATA%\BeanStudio\desktop-settings.xml`；音效是同目录 `sound-settings.xml`。只保存在本机，不上传媒体和配置。正常监测不持续写截图；主动诊断、校准与启动错误文件仍按原逻辑保存，自己导出的诊断可按需删除。

构建仍需 64 位 Windows 10 1903+ / Windows 11、.NET Framework 4.8 或 4.8.1，以及原生 OCR 对应的 Visual C++ x64 运行库。在本工程目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
# 运行目录已准备好依赖时
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -SkipDependencies
```

保留 `Tesseract.dll`、`x64`、`tessdata`、`sounds` 和 `clock-templates.txt` 与 EXE 同目录。本次没有迁移 UI 技术栈；从 GitHub 克隆得到的是远端当时的版本，不自动等于这个本地 V5.8 工程。

检查覆盖快捷键保存 / 冲突 / 取消 / 关闭注销、扫描线程与暂停规则、四种浮窗和极值大小、进程计数器不可用情况，以及原豆子 / 时钟 / 音效状态。新增 `--resize58-test <报告目录>` 使用自建窗口验证实际 WGC 放大重定位和来源关闭处理。验证以 [本次汇总](V58_VERIFICATION.md) 为准，不能将此前版本的通过结果记作 V5.8 新检查，也不能把合成窗口结果换成真实 MuMu 的准确率或延迟保证。
