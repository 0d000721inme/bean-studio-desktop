# 下一模型交接 · Windows V5.8.1

本版以已交付 V5.8 为基线，用户反馈恢复点应与倒计时同级、要求恢复小数显示，并报告开启监测后拖动窗口卡顿。只改展示与响应路径，没有改变识别门槛、捕获读回上限、游戏时钟识别方法或 15 秒期限语义。本版源码同步到主分支及 `v5.8.1` 标签；发布页保留已验证的原运行 ZIP，EXE 未因上传而重新编译。

先看 [V5.8.1 验证](V581_VERIFICATION.md) 和 [使用说明](V581_USAGE.md)，旧接口与计时规则见 [V5.8 交接](NEXT_MODEL_V58.md)。V5.8 文档里的整秒默认、旧浮窗尺寸及当时 EXE 哈希属于历史；不要照旧值判断本版。

## 文件与边界

- `RecoveryDisplay.cs`：只解析引擎恢复点文本用于展示。`Parse` 返回 `Value / Caption / Status / HasValue / IsApproximate`。数字仅接受明确恢复点前缀和 0–60 范围；未知、读取中、回合不足不造数。`≈` 和中途补算说明保留。
- `GlassUI.cs`：两个主要数字等字号等区域，主窗近似标记放在恢复点标题，避免 `≈59.99` 裁切；`ApplySnapshot` 缓存恢复点解析。豆点、Badge、轨道按可见值变化才重绘。系统移动消息只改变 `interactiveMoving` 展示节流；退出、取消、丢失捕获均清理。主数字继续刷新，延后 ROI 克隆及曲线，退出后补更新。
- `Overlay.cs`：四风格双主信息、透明背景、缩放和左右命中保留。位置变化复用已有 Windows 表面；拖动时表面最多约 10 Hz，松手立即补最新状态，常态小数约 33 ms。丢失鼠标捕获会取消节流。
- `BeanTimer.cs`：`HudHost.UpdateHud` 无豆时仍传原 `Snapshot.Recovery`，无豆提示和恢复点并存；新增本版 CLI。没有改 `Counter`、`Engine.Loop`、deadline 或音效。
- `WindowCapture.cs`：只有展示状态改为 `volatile string` 无锁读取，原捕获/暂停生命周期锁保持。原因是旧 `Status` getter 与兼容截图的 `CopyFromScreen` 共用锁，UI 读状态也会等截图。不要误写成整个捕获已无锁，或据此宣称 WGC/GPU 所有争用都解决。
- `DesktopSettings.cs`：默认 `WholeSeconds=false / ShowRecovery=true`。接受 XML V1 和 V2，V1 仅迁移这两个展示字段，其余偏好保留；保存写 V2，之后尊重用户主动设置。加载本身不写用户设置文件，不修改音效或校准。

## 本版检查入口

`--overlay581-test <目录>` 验证两数字、解析、四风格/大小、表面缓存和拖动。

`--drag581-test <目录>` 验证主窗双数字、稳定绘制、自己窗口的移动消息、WM_TIMER 小数继续、原 deadline/trigger 不变、取消/丢捕获清理。不会发现或打开 MuMu；它不能作为真实模拟器拖动帧率。

`--capture-status581-test <目录>` 只人为持有截图锁 250 ms，证明新状态读取不等该锁；不创建捕获会话或读取用户屏幕。

旧设置、浮窗、Studio、暂停、时钟、重定位等入口仍在；新增主控件使旧 Studio 检查数增加，默认小数与新尺寸使旧浮窗预期相应更新。脚本固定数量必须以实际报告更新，不能为“通过”删除有效断言。GUI/WGC 检查串行运行，避免菜单焦点/遮挡干扰。

## 保留的限制

本版查明并修复了具体的 UI 重绘和锁等待路径；没有在用户实际 MuMu 对局中测量卡顿改善比例。WGC 仍至多 60 Hz 整窗读回，硬件/驱动和模拟器渲染可能争用资源。不能通过暂停检测来伪装拖动流畅，也不能丢掉估算/未知标签来伪装恢复点精确。未来改采样率应重新测量真实新帧确认和端到端延迟。

构建保持 C# / WinForms / .NET Framework 4.8 x64，官方 OCR 依赖不变；保留 MIT 和所有第三方通知，不上传用户截图、媒体、诊断或本机设置。
